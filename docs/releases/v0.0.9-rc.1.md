# Hyper Git - Agentic Git v0.0.9-rc.1 — 0.0.9 候选版

> ⚠️ **Release Candidate**：本版本是 0.0.9 正式版的候选版（预发布），聚焦**提交/日志视图整合与可用性增强**。已通过本地类型/Lint/324 单元测试与 Extension Development Host 实测，欢迎在 [Issues](https://github.com/ThreeFish-AI/hyper-git/issues) 反馈问题；正式版将在收口反馈后发布。

本次迭代围绕「消除冗余、对齐全 IDE 体验」做了一次内聚重构：移除与 Commit 视图数据同源的冗余 CHANGES 树视图并把其全部能力平移入 Commit webview，同时为 Commit / Log 两个文件列表补齐 IntelliJ / VS Code SCM 同款的「按目录分组」形态，并为 Log 提交图补齐悬浮详情。侧边栏视图数由 7 降为 6，提交工作流更聚焦。

---

## ✨ 亮点速览

- **Commit 视图整合（移除 CHANGES）**：原 CHANGES 树的活动 Changelist 与 Commit 视图完全重复，现删除 CHANGES，文件单击看 Diff、单文件右键菜单、Changelist 切换与管理、Git 工具栏与未提交角标**零回归**平移入 Commit 视图。
- **文件列表按目录分组**：Commit 与 Log 的变更文件列表新增 List / Tree 段控，树形按目录折叠（对齐 VS Code `explorer.compactFolders`），Commit 树附目录级三态复选框；偏好按视图记忆，切换零往返。
- **Log 提交悬浮详情**：悬停任一提交行 ~400ms，浮层展示分支/标签/HEAD、完整提交消息（subject + body）、作者与提交者、绝对+相对时间、完整 SHA；与 CI 浮层互斥，`i` 键开 `Esc` 关。

## 🧩 完整能力

### Commit 视图整合（原 CHANGES 视图能力全量平移）
CHANGES 树视图与 Commit 视图顶部「Active Changelist」展示同一份数据（同源 `service.getChanges()` + `registry.getGroups()`），属冗余。本版本删除 CHANGES 视图，其独有能力全部迁入 Commit webview：

- **文件交互**：活动 Changelist 文件单击打开原生 Diff（HEAD ↔ Working）；右键原生 QuickPick 菜单执行 Open Diff / Move to Changelist… / Show History / Stage·Unstage Hunks… / Add to .gitignore / Discard Changes（含 discard 确认框）。
- **Changelist 管理**：头部 `<select>` 切换活动列表；`⋯` 菜单新建 / 重命名 / 删除（默认列表不可改名删除）。
- **Git 工具栏与角标**：原挂在 CHANGES 标题栏的 refresh / push / pull / fetch / push 对话框 / updateProject / createPatch / applyPatch 迁至 Commit 视图标题栏（去掉与 webview 内按钮重复的 commit / commitAndPush）；活动栏未提交数角标改由 Commit `WebviewView.badge` 承载（首帧未 resolve 以 `pendingBadge` 兜底）。
- **命令实参单一事实源**：文件级命令统一接受 `ChangeItem | 路径字符串`，host 经 `resolveChange` 回落 `service.getChanges()` 解析；右键菜单复用 Log 视图「webview `postMessage` → host `showQuickPick` → 复用既有命令」范式，键盘可达、无 CSP/焦点陷阱。视图刷新改由 `registry/service.onDidChange → refreshAll → commitView.refresh()` 驱动。

### 变更文件目录树切换（Group By Directory）
Commit 视图活动 Changelist 文件列表、Log 视图选中提交的「Changed Files」列表，均支持在**平铺列表**与**按目录分组的树形**之间切换（工具栏 List/Tree 段控），默认平铺，偏好按视图各自记忆。

- **host 算树、webview 渲染**：新增纯逻辑 `engine/tree/file-tree.buildFileTree`，host 侧按同批扁平文件路径构建目录树随 payload 下发（复用 graph-layout「host 算、webview 渲」范式，规避内联脚本无法 import engine 的 Split-Brain）；叶子以 `fileIndex` 回指扁平列表，不复制条目数据。
- **对齐 VS Code / IntelliJ**：目录在前、文件在后，数字感知升序稳定排序；单目录子链 compact 折叠（如 `a/b/c` → `a/b`，对齐 `explorer.compactFolders` 默认行为）。
- **Commit 目录三态**：树形叶子勾选 + 目录级三态复选框（全选/部分/未选）级联，Select All 基于全量文件；Log 为只读浏览。切换/折叠零 host 往返。

### Log 提交悬浮详情（Commit Tooltip）
鼠标悬停 Log 视图任一提交行，以浮层快速展示该提交的完整信息，**零往返、零延迟**（数据随首帧图下发）：

- **内容**：所在本地/远程分支、标签、HEAD；完整提交消息（subject + body，多行保留、超长滚动 + 截断）；作者 `name <email>`；（与作者不同时的）提交者；作者/提交时间（绝对 + 相对）；完整 SHA。
- **复用 CI 浮层范式**：浮层置于虚拟滚动 `#rows` 之外（重写行 DOM 不销毁）；与 CI 浮层互斥；滚动、刷新、切换范围、增量数据均即时消隐；`i` 键打开、`Esc` 关闭（`stopPropagation` 不与 `Enter`→提交菜单冲突）；移除 chips 原生 `title` 双重气泡。
- **取数扩展**：`git log --format` 增 `%cn`（提交者）、`%cI`（提交时间）、`%b`（正文，置末字段，记录以 RS 终止、字段以 NUL 分隔，正文内换行/管道/反斜杠不被误判为边界）；正文 host 侧 `capBody` 截断至上限以控 1000 行 payload。
- **XSS 安全**：分支名/标签/作者/正文等一切外部内容均经 `esc()` 转义后注入。
