# Hyper Git - Agentic Git v0.0.20 — Delete Remote Branch 陈旧远程分支修复 · 删除失败可诊断

> 本版核心：**修复 Branches 视图「Delete Remote Branch」对「服务端已不存在」的远程分支误报失败、且删除失败时不显示任何原因的问题**。PR 合并后被 GitHub 自动删除的分支，在下次 `fetch --prune` 前会以陈旧 remote-tracking ref 的形式留在 Branches 视图中；对它执行删除曾被服务端拒绝并回显笼统的「N failed」。本版把这类分支识别为「目标态已达成」——按成功收尾、就地清理本地陈旧 ref；真正的失败（保护分支拒绝 / 认证 / 网络）则在通知中逐分支附上 git 的真实报错，并可直达 Show Output 查看完整输出。

---

## ✨ 亮点速览

- **陈旧远程分支不再误报失败**：删除「服务端已无此 ref」的分支（典型：PR 合并后远端自动删除）时，通知如实标注 `N already gone on remote (pruned local tracking ref)` 并同步清理本地陈旧 tracking ref，视图中的「幽灵分支」就地消失。
- **删除失败可诊断**：真失败不再只回显笼统的「N failed」——保护分支拒绝、认证失败、网络错误等真实原因（stderr 优先）逐分支附在通知中，超长折叠单行、超 4 条截断标注；配合 **Show Output** 按钮直达 Hyper Git Console 查看完整输出。
- **错误文本提取单一事实源（`gitErrorText`）**：新增 engine 纯函数统一「非空白 stderr 优先 → message → 兜底」提取语义；Push 对话框 / Update Project / Merge 对话框的失败通知随之升级为 stderr 优先，真实原因直达。
- **受保护主干与既有防护不变**：main / master 硬阻断、当前分支上游软警示、删除前 modal 确认等既有行为全部保留。

## 🧩 特性详述

### 1. Delete Remote Branch 三桶语义（#147）

删除循环按结果三桶处理，通知如实计数：

- **成功**：`Deleted remote branch origin/foo`（单条）/ `Deleted N remote branches`（多条）；
- **服务端已无此 ref（already gone）**：`git push <remote> --delete` 被服务端以 `remote ref does not exist` 拒绝时，经 engine 分类器 `isRemoteRefMissingError`（匹配 git 2.x 规范文案及旧服务端变体，大小写不敏感）识别——该分支的目标态（服务端无此分支）已天然达成，按成功收尾并清理本地陈旧 tracking ref；通知单列 `N already gone on remote (pruned local tracking refs)`，不以误导性的「Deleted 0 …」开头；
- **真失败**：保护分支拒绝（如删除远端当前分支）、认证 / 网络错误等——失败原因经 `gitErrorText` 提取（stderr 优先），通知逐分支附 `branch (原因)`；失败级通知联动 **Show Output** 查看完整 stderr。

### 2. 错误文本提取单一事实源 `gitErrorText`（#147）

- 新增 `engine/git-state/git-error.ts`（零 vscode 依赖，全量单测）：统一 CLI 通道（`execGit` 透传的 `.stderr`）与 vscode.git API 通道（GitError）的提取语义——非空白 stderr 优先（trim 后返回），回退 message，最终 `String(e)` 兜底；
- `remote-commands` / `history-commands` 的两处内联实现改为引用该单一事实源；Push 对话框 / Update Project / Merge 对话框失败通知由通用 message 升级为 stderr 优先（如「无上游」「non-fast-forward」等失败原因直接可读）；
- 存量 adapter 中约 13 处旧式内联 `errMsg`（只读 message）为预先存在的迁移债，将在后续版本逐步迁移，不影响本版行为。

## ⚙️ 升级与兼容

- **无破坏性变更**：全部既有命令、视图与配置项保留；删除确认弹窗、受保护主干（main / master）硬阻断、当前分支上游软警示行为与 v0.0.19 一致；
- **行为改进**：仅删除分支场景的通知文案与失败路径变化（更诚实、更可诊断）；`already gone` 分支的本地 tracking ref 现会被主动清理（此前仅成功删除项清理）。
