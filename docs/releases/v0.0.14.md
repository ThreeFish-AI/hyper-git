# Hyper Git - Agentic Git v0.0.14 — 修复 GRAPH 视图提交记录时间倒序

> 修复 **GRAPH 视图**「All」范围下提交记录**未按时间倒序**排列的问题：此前列表前段日期正常递减，中段却会「回跳」到最新日期——较新的旁支提交被错误地挤到列表底部。本版令提交严格按**作者日期倒序**呈现，跨分支提交正确交错。

> 本版为纯取数排序修复，未改动任何 `viewType`、消息协议、`webview.setState` 形状、布局算法与配置项，旧状态无需迁移。

---

## ✨ 亮点速览

- **提交记录严格时间倒序**：GRAPH 视图取数参数由 `--topo-order` 改为 `--author-date-order`，从较旧提交分叉、但日期较新的旁支提交不再被「成块」挤到列表末尾，日期列自上而下单调递减、不再回跳。
- **泳道不受影响**：DAG 彩色泳道（lane）布局所依赖的「子提交在父提交之上」拓扑不变量在新排序下依然严格成立，连线与分叉渲染保持正确，无断裂、无变形。
- **零协议/交互回归**：仅一行取数参数变更，数据协议、布局算法、引用胶囊、悬浮卡、范围切换（All / Current / Checkpoints）、增量加载与过滤（author / grep / path）全部沿用。

## 🧩 问题与修复

### 现象

在「All」范围下，提交记录本应严格按时间倒序（最新在顶部）。实际却出现：列表前段（如 `2026-07-05` → `2026-05-25`）日期正常递减，但中段之后日期**回跳**回最新的 `2026-07-05`——一批远端旁支提交（如安全修复、依赖升级等分支）被整块排到了列表底部，与「按时间浏览历史」的直觉严重不符。

### 根因

GRAPH 视图的提交顺序此前完全由 `git log` 的 `--topo-order`（拓扑序）参数决定，管道各层均无二次排序。`--topo-order` 在保证「子在父之上」的同时，会额外把**不同分支的历史「成块」输出**——一条分支的提交整块列完，再切到下一条。当仓库存在从较旧提交分叉、但提交日期较新的旁支时，这些提交便被整块下放到列表末尾，形成「日期回跳」。这是 `--topo-order` 的设计特性，并非按日期排序。

### 修复

改用 `--author-date-order`：它同样保证 DAG 泳道算法依赖的「子在父之上」拓扑不变量，但在此约束下**按作者日期倒序**排列提交，使跨分支提交正确交错。之所以选「作者日期」而非「提交者日期」，是为了与 GRAPH 视图**日期列实际显示的时间**保持一致——排序键与显示键对齐，避免出现「列内日期看似仍乱序」的二次困惑。
